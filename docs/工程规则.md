# 视频格式转换器 · 工程规则

> 本文是本项目的**开发约束说明**。开发与协作时遵守本文。
> 产品形态：Windows 桌面应用 · 主力语言：**Python**
> 规则用语：`必须` = 不做则不符合交付标准；`应当` = 默认要做；`可以` = 有余力再做；`禁止` = 不得采用

---

## 0. 一句话目标

做一个**给人用的 Windows 桌面客户端**：打开就能看懂，能加载视频信息与缩略图，能用 ffmpeg **命令行**完成格式转换，并把关键工程决策写清楚。

不是脚本、不是网页 Demo、不是 ffmpeg 命令生成器。

## 2. 硬约束（违反即不符合交付标准）

1. **必须**做成桌面客户端。`禁止` Streamlit / Gradio / FastAPI+网页 / Jupyter / 纯 CLI / 纯 tkinter 默认皮肤脚本窗。
2. **必须**用 Python 作为应用主体语言。
3. **必须**用 ffmpeg **命令行**完成转换与缩略图抽取。`禁止` 接入 ffmpeg 官方 C API / 依赖 `ffmpeg-python` 当核心（包装 CLI 可以，但命令必须可在日志里原样看到）。
4. **必须**能加载并展示视频信息，**必须**能获取并展示缩略图。
5. **必须**在过程文档中保留：会话总结、开发者决策、对 AI 的反馈（如有使用）。
6. **必须**把可运行仓库推到可访问的远程（如 GitHub public）。
7. **必须**自己当用户走通主路径，并留下测试记录。没有实测截图/记录视为未完成。
8. **必须**按 `docs/阶段任务.md` 的阶段顺序交付。未通过当前阶段验收，禁止开始下一阶段。
9. 界面文案 **必须** 中文。错误信息 **必须** 让非开发者也能看懂。
10. 转换过程 **必须** 不冻结窗口。`禁止` 在 UI 线程里同步跑 ffmpeg。

## 3. 技术选型（已锁定，禁止再讨论替代方案）

### 3.1 锁定

| 层 | 选择 | 原因（写进决策文档） |
|---|---|---|
| UI | **PySide6（Qt for Python）** | Windows 原生桌面客户端；Python 可独立完成；与「客户端」产品形态一致 |
| 元数据 | `ffprobe` CLI + JSON | 稳定、信息不靠猜文件名 |
| 缩略图 | `ffmpeg -frames:v 1` 抽帧到临时 png/jpg | 符合「只用命令行」 |
| 转换 | `ffmpeg` CLI | 产品需求 |
| 并发 | `QThread` / `QProcess` | 界面不卡；`QProcess` 可直接读进度与取消 |
| 配置 | 本地 JSON（上次目录、上次格式） | 第二次打开像给人用的软件 |
| 打包 | `PyInstaller`（有时间必须做） | 可交付可执行包 |

许可证：用 **PySide6**，不用 PyQt6（GPLv3 对公开仓库不友好）。

### 3.2 禁止选型

| 禁止 | 原因 |
|---|---|
| tkinter / CustomTkinter 作为主 UI | 观感偏脚本工具，不像正式桌面产品 |
| Electron / Tauri / WPF | 偏离 Python 主力，范围失控 |
| 浏览器页当主界面 | 与「桌面客户端」产品形态冲突 |
| 直接 `os.system` 拼命令 | 无法取消、无法进度、有注入风险 |

若 AI 建议改成网页或 tkinter：**必须拒绝**，并记入反馈文档。

## 4. 产品定位（设计时先问：人怎么用）

**用户**：会用电脑、不一定会命令行的人。  
**任务**：把一个视频转成常用格式，并在转换前确认「这就是我要的那个文件」。  
**成功**：输出文件能播放，体积/清晰度符合所选预设，用户知道文件在哪。

主路径（必须 1 分钟内走完）：

1. 打开软件
2. 选择或拖入视频
3. 立刻看到封面 + 时长/分辨率/编码/帧率/大小
4. 选目标格式（或预设）
5. 选保存位置（默认有合理路径）
6. 点开始，看进度，可取消
7. 完成后能打开文件或打开所在文件夹
8. 失败时看到原因和下一步（例如「没有 ffmpeg」「输出被占用」）

任何功能如果让主路径变复杂，降为高级选项，默认折叠。

## 5. 功能分级

### P0（没有就不交）

- 选择本地视频（文件对话框）
- 展示信息：文件名、路径、大小、时长、宽高、视频编码、音频编码、帧率、比特率（拿不到的项显示「未知」，禁止空白或报错崩溃）
- 展示缩略图（抽帧失败时显示占位图 + 原因，禁止整窗空白）
- 选择输出格式与输出路径
- 调用 ffmpeg 转换
- 进度、完成、失败三种状态
- 转换中禁止再次点击开始；允许取消
- 检测 ffmpeg / ffprobe 是否可用；不可用时阻断转换并告诉用户怎么处理
- 中文界面、关闭确认（转换中；probe/thumb 进行中关窗也必须等线程结束，禁止崩溃）

### P1（优化，至少完成 3 项，建议全做）

这些才是「按自己想法做优化」，每项必须能用一句话说清对人的好处：

1. **拖放文件**：比找对话框快
2. **常用预设**：如「通用 MP4（H.264 + AAC）」「压缩体积」「提取音频 MP3」「高质量 1080p」——用户不懂 CRF/码率
3. **ffmpeg 进度解析**：用 `-progress pipe:1` 把百分比和剩余时间显示出来
4. **记住上次目录和上次预设**
5. **完成后打开文件夹 / 播放**
6. **覆盖前提示**；文件名冲突自动加后缀也可以，但必须可预期
7. **完成后显示体积变化**（如 `12.3 MB → 4.1 MB（压缩 67%）`）——交付截图里一眼能看懂
8. **输出文件名预览**
9. **日志面板默认收起**：给自己排错，不挡普通用户
10. **PyInstaller 打包** + `ffmpeg.exe` 检测（不强制把 ffmpeg 打进包，但 README 要写清）

硬件加速（NVENC/QSV/AMF）改为**可选**：必须独立完整参数（不要把 `libx264 -crf` 换成 nvenc），失败回退。时间不够优先保证主路径和 GitHub 链接。

### P2（时间不够就砍，写进决策文档「故意不做」）

- 批量队列
- 剪裁时间段、旋转、字幕
- 自动更新
- macOS / 多语言
- 云转码、账号系统
- 内置模型、Agent、RAG

P2 出现在界面上但点了不能用，视为质量事故。

## 6. 界面规则（交付时优先看选型，其次看像不像产品）

1. **必须**是单窗为主。不要一堆无标题弹窗。
2. 布局固定为四区，不要自由发挥成控制台：
   - 顶：文件选择 / 拖放区
   - 左或中：缩略图
   - 右：视频信息
   - 底：格式、输出路径、进度、主按钮
3. 主按钮在同一时刻只表达一个动作：`开始转换` / `转换中…` / `打开文件夹`。
4. 危险操作（取消、覆盖、退出进行中任务）必须可撤销或二次确认。
5. 颜色只用来表达状态：空闲 / 进行 / 成功 / 失败。不要装饰性彩虹。
6. 缩略图保持比例，不要拉伸变形。
7. 长路径省略显示，但 tooltip 给全文。
8. 最低可用分辨率：1280×720 窗口能完整使用，不允许控件被裁切。
9. 字体、间距、对齐按桌面软件而不是网页落地页。
10. `禁止` 把原始 ffmpeg 命令作为唯一操作方式暴露在主界面。命令可以放进「高级/日志」。

## 8. ffmpeg 命令行规则

1. 先 `ffprobe` 再展示；probe 失败仍显示文件名和大小，其它为未知。
2. 缩略图：优先在 `duration * 0.1` 处抽 1 帧；时长未知则用 `-ss 1`。抽帧应当快速（先 seek 再 decode）。
3. 转换命令必须可复现：日志用 shell 引用展示（`list2cmdline`），执行仍用 `list[str]`。
4. 进度：加 `-progress pipe:1 -nostats`。**优先解析 `out_time=HH:MM:SS`**；`out_time_us` 次之；`out_time_ms` 只作兜底（很多版本实际是微秒，禁止一律当毫秒）。
5. 取消：`terminate` → wait → `kill` → wait，**再删**不完整输出。不要 kill 后立刻删。ffmpeg 不 fork，不必杀进程树。
6. 输入输出路径按原样传入参数列表，正确处理空格和中文路径。
7. 启动时查找顺序：配置里的路径 → `PATH` → 常见安装位置。找不到就引导，不要崩溃。
8. `禁止` 默认 `-y` 静默覆盖；覆盖策略走 UI。
9. 预设必须是完整可用的参数集，不允许「选了 MP4 但视频不能播」。原画转封装须 `-sn` 并可选映射音轨，避免 mkv 字幕流导致 copy 失败。
10. 软件编码兜底：`libx264` + `aac` 作为默认通用 MP4。
11. `ffprobe`/`ffmpeg` 命令 **不要加 `--`**。
12. QProcess **禁止** MergedChannels；stdout 进度、stderr 日志；残行 buffer。
13. `closeEvent` 必须等待 probe/thumb/convert 全部结束。

建议默认预设（P0 至少 2 个可用）：

| 预设名 | 用途 | 关键参数方向 |
|---|---|---|
| 通用 MP4 | 微信/播放器都能播 | H.264 + AAC + `+faststart` |
| 压缩体积 | 发给别人 | 更高 CRF，限制音频码率 |
| 提取音频 | 只要声音 | `-vn` + MP3/AAC |
| 原画转封装 | 尽量不重编码 | `-map 0:v:0 -map 0:a:0? -c copy -sn`（失败则提示该组合不能 copy） |

## 9. AI 工程规则（本项目真正打分点）

你是开发者，AI 是加速器。读者会读文档判断你有没有被工具带着跑。

### 9.1 必须遵守的工作方式

1. 每个会话开始先读本规则和 `DECISIONS.md`，已锁定的选型不要重开。
2. 先写/改验收标准，再让 AI 写代码。
3. AI 给出的每一份关键代码，你必须能回答三句：
   - 它做了什么
   - 边界情况是什么
   - 错了会怎样
4. 跑不通时，先看日志和复现步骤，再问 AI。禁止连续「再试一种」而不记录失败原因。
5. AI 建议增加 P2 功能时默认拒绝。
6. 安全：不把密钥写入仓库；不 `shell=True`；不执行来路不明的命令。

### 9.2 必须记录的三类文档

**SESSION_SUMMARY.md（会话总结）**  
每个有效开发会话结束时追加一节，禁止最后一天一次性编造。至少包含：

- 时间与目标
- 实际完成
- 使用了哪些 AI 工具（Cursor / 模型名即可）
- AI 做了什么、人做了什么
- 未解决问题

**DECISIONS.md（决策）**  
只记录有取舍的决定，格式固定：

```
### D-编号 标题
- 日期：
- 背景：
- 选项：A / B / C
- 选择：
- 原因（对人的好处，或对范围/风险的控制）：
- 后果：因此不做……
```

至少要有这些决策（没有就要补）：

- D-01 为什么 PySide6 而不是网页/tkinter
- D-02 为什么 QProcess 而不是同步 subprocess
- D-03 预设怎么设计（面向人，而不是面向编码器专家）
- D-04 硬件加速做不做、怎么回退
- D-05 打包策略：ffmpeg 内置还是外置
- D-06 哪些 P2 故意砍掉

**AI_FEEDBACK.md（对 AI 的反馈）**  
记录审查，不是表扬信。每条：

```
### F-编号
- 现象：AI 给了什么
- 问题：错在哪 / 哪里不能直接用
- 处理：你怎么改的
- 规则：以后禁止再犯
```

必须至少 5 条真实反馈（例如：在 UI 线程调用 ffmpeg、用 tkinter、shell=True、忽略中文路径、抽帧先 decode 再 seek 导致很慢、失败只 print 不提示用户）。

## 10. 测试规则（对应「不要自己都用不明白甚至都不测试」）

`TEST_REPORT.md` 必须有真实文件实测，不能只写「测试通过」。

### 10.1 每次发版前手工清单

| ID | 步骤 | 期望 |
|---|---|---|
| T01 | 无 ffmpeg 启动 | 明确提示，不崩溃 |
| T02 | 打开 mp4 | 信息 + 缩略图出现，窗口不卡 |
| T03 | 中文路径、空格路径 | 同样成功 |
| T04 | 开始转通用 MP4 | 进度变化且完成前不超过 99%，完成后可播放 |
| T05 | 转换中点取消 | 停止、界面恢复、不留下坏文件或有说明 |
| T06 | 转换中再点开始 | 无效或明确拒绝 |
| T07 | 输出已存在 | 询问覆盖或自动改名，行为与文案一致 |
| T08 | 损坏/非视频文件 | 人话错误，不崩 |
| T09 | 关闭进行中窗口 | 确认后结束进程 |
| T10 | 连续转两个文件 | 第二次仍正常（无残留状态） |
| T11 | 改预设后输出后缀 | 只换后缀，目录和主干不变 |
| T12 | 输出路径等于源文件 | 拒绝转换，源文件完好 |
| T13 | 无音轨选提取 MP3 | 点开始前即提示，未启动 ffmpeg |

### 10.2 应当有的自动化

- 预设参数列表构造；切预设只换输出后缀
- 进度文本解析（含 clamp 到 99）
- 路径参数不会变成 shell 字符串；输出不得等于输入

没有视频素材时：用 ffmpeg 自己生成 2 秒测试彩条视频，并写进测试说明。

### 10.3 证据

测试报告里贴：

- 主界面截图（有视频信息 + 缩略图）
- 转换中截图（有进度）
- 成功后播放器打开输出文件的截图
- 至少一次失败提示截图

## 11. 怎么执行（给 AI）

**不要按天数拆。按阶段拆。任务清单入口：`docs/阶段任务.md`。实现配方：`docs/AI执行方案.md`。**

进度只认 `docs/PHASE_STATUS.md`。每次会话：

1. 读规则、阶段任务、执行方案、决策、阶段状态
2. 只做第一个未 `done` 的阶段
3. 按该阶段「本阶段文件 + 任务清单 + 验收」逐项完成（接口/文案/验证命令见 `docs/AI执行方案.md`）
4. 验收通过后把状态改为 `done`
5. 更新会话总结；有决策/审查则写对应文档
6. 停下。除非用户明确说继续下一阶段

阶段顺序固定：S0 脚手架 → S1 界面骨架 → S2 检测 ffmpeg → S3 视频信息 → S4 缩略图 → S5 转换主路径 → S6 进度/取消/覆盖 → S7 优化 → S8 实测 → S9 打包与 README → S10 过程文档收口。

P0 对应 S0–S6。P1 对应 S7。过程与提交对应 S8–S10。禁止先做后面阶段。

## 12. README 必须包含

面向两个读者：交付验收方、以及以后重装环境的人。

1. 这是什么：一句话 + **主界面截图** + 标明「Windows 原生桌面客户端（PySide6/Qt）」（读者第一眼看选型）
2. 环境：Windows、Python 版本、ffmpeg 如何安装
3. 开发启动命令
4. 打包后如何运行（若有）
5. 功能列表：P0 全写，P1 只写已做的
6. 架构简述（配目录）
7. 过程文档链接：`docs/SESSION_SUMMARY.md` 等
8. 已知限制（诚实写）

`禁止` 把会话记录只留在本地。`禁止` README 只有 pip install 没有产品说明。

## 13. Git 提交规则

- 仓库名清晰，例如 `video-format-converter`
- 提交信息写原因，不写 `update` `fix`
- `.gitignore`：`__pycache__`、`.venv`、输出视频、临时缩略图、`.idea`
- `禁止` 提交大于数 MB 的演示视频；截图可以
- 提交按阶段切：`feat(S3): ...`。不要一个超级提交，也不要一堆无意义 `update`
