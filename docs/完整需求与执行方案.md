# 第一部分　需求规格

## 1. 用户、任务、成功

- **用户**：会用电脑、不一定会命令行。
- **任务**：把一个本地视频转成常用格式；转换前能确认「这就是我要的那个文件」。
- **成功**：输出能播放；体积/清晰度符合所选预设；用户知道文件在哪；失败时知道下一步。

主路径必须约 1 分钟走完：

1. 打开软件
2. 选择或拖入视频
3. 立刻看到封面 + 时长 / 分辨率 / 编码 / 帧率 / 大小
4. 选目标格式（预设）
5. 选保存位置（默认有合理路径）
6. 点开始，看进度，可取消
7. 完成后能打开文件或打开所在文件夹
8. 失败时看到原因和下一步（没有 ffmpeg、输出被占用等）

任何让主路径变复杂的东西，做成高级/折叠，或直接不做。

## 3. 界面需求

必须单窗为主。四区布局，不要做成控制台：

```
+--------------------------------------------------+
| 顶：拖放/选择文件区（「选择视频」+「或把视频拖到这里」） |
+------------------------+-------------------------+
| 左：缩略图（16:9 占位） | 右：信息表（键值对）        |
+------------------------+-------------------------+
| 底：预设、输出路径、浏览、进度、状态                 |
|     主按钮「开始转换」  次按钮「取消」（默认禁用）     |
|     「详细日志」可折叠，默认收起                     |
+--------------------------------------------------+
```

规则：

- 窗口标题：`视频格式转换器`
- 初始大小 `1100×720`，最小 `960×640`
- `1280×720` 下控件不能被裁切
- 主按钮同一时刻只表达一个动作：`开始转换` / `转换中…` / `打开所在文件夹`
- 缩略图保持比例，禁止拉伸
- 长路径省略显示，tooltip 给全文
- 颜色只表达状态：空闲 / 进行 / 成功 / 失败，不要装饰性彩虹
- 危险操作（取消、覆盖、退出进行中任务）二次确认
- **禁止**把原始 ffmpeg 命令当作主界面唯一操作方式；命令只进默认收起的日志
- 不要网页落地页风格

信息表固定行（顺序不要改）：文件名、路径、大小、时长、分辨率、视频编码、音频编码、帧率、比特率。

文件对话框过滤器：

```
视频文件 (*.mp4 *.mkv *.mov *.avi *.webm *.flv *.wmv);;所有文件 (*.*)
```

## 4. 转换预设需求

默认选中第一项。参数必须是完整可用集合，不允许「选了 MP4 但视频不能播」。

| id | 界面名称 | 后缀 | 参数（写成 list[str]） |
|---|---|---|---|
| `mp4_compat` | 通用 MP4 | `.mp4` | `-c:v` `libx264` `-preset` `medium` `-crf` `23` `-c:a` `aac` `-b:a` `128k` `-movflags` `+faststart` |
| `mp4_small` | 压缩体积 | `.mp4` | `-c:v` `libx264` `-preset` `slow` `-crf` `28` `-c:a` `aac` `-b:a` `96k` `-movflags` `+faststart` |
| `mp3_audio` | 提取音频 MP3 | `.mp3` | `-vn` `-c:a` `libmp3lame` `-q:a` `2` |
| `copy_mux` | 原画转封装 | `.mp4` | `-map` `0:v:0` `-map` `0:a:0?` `-c` `copy` `-sn` |

`copy_mux` 必须带 `-sn` 和可选音频映射：mkv 里的字幕流用裸 `-c copy` 转到 mp4 会失败。失败人话仍用 W21。

`mp3_audio`：若 `MediaInfo.audio_codec is None`，**选中该预设时立刻**状态栏 W31、主按钮禁用，禁止开转。ffmpeg 万一仍失败，`humanize_ffmpeg_error` 同样用 W31，不要套用 W21。

软件编码兜底永远是 `libx264` + `aac`（通用 MP4）。

**硬件加速（R20，可选，仅时间有余）：** 禁止「把 libx264 换成 h264_nvenc」——NVENC 用 `-cq`，QSV 用 `-global_quality`，都不认 `-crf`。必须写成**独立完整 args**，失败再跑软件预设。界面不要单独做「GPU」开关。参考参数（可按本机微调，但必须是完整列表）：

| 对应软件预设 | 编码器 | 完整 args 方向 |
|---|---|---|
| 通用 MP4 | `h264_nvenc` | `-c:v h264_nvenc -preset p4 -cq 23 -c:a aac -b:a 128k -movflags +faststart` |
| 压缩体积 | `h264_nvenc` | `-c:v h264_nvenc -preset p5 -cq 28 -c:a aac -b:a 96k -movflags +faststart` |
| 通用 MP4 | `h264_qsv` | `-c:v h264_qsv -preset medium -global_quality 23 -c:a aac -b:a 128k -movflags +faststart` |
| 通用 MP4 | `h264_amf` | `-c:v h264_amf -rc cqp -qp_i 23 -qp_p 23 -c:a aac -b:a 128k -movflags +faststart` |

尝试顺序：nvenc → qsv → amf。失败状态栏 W23，然后用原来的软件 `args` 重跑。

## 5. 非功能与工程需求

- 路径原样进入参数列表，正确处理空格和中文路径
- 启动查找 ffmpeg：环境变量 `VFC_FFMPEG` / `VFC_FFPROBE` → `PATH` → `C:\ffmpeg\bin\` → `C:\Program Files\ffmpeg\bin\`
- 所有外部命令记录：完整 argv、耗时、退出码、stdout/stderr；**展示给用户复制时**用 Windows 引用（`subprocess.list2cmdline`），执行仍是 list
- 取消：`terminate` → `waitForFinished` → 仍活着再 `kill` 再 wait；**等进程退出后再删**不完整输出。ffmpeg 不 fork，不要搞「杀进程树」
- 覆盖策略走 UI，禁止静默 `-y`
- 抽帧：优先在 `duration * 0.1` 处 1 帧；时长未知则 `-ss 1`；先 seek 再 decode；临时文件带自增序号，避免 QPixmap 路径缓存串图
- 进度：`-progress pipe:1 -nostats`。**优先解析 `out_time=HH:MM:SS.mmm`（无歧义）**。`out_time_us` 次之。`out_time_ms` 只作兜底，且多数构建里它实际是**微秒**，禁止一律 `/1000` 当毫秒（否则进度永远约 0%）
- 单测至少覆盖：预设命令构造、**真实风格的 `out_time=` 行**、probe JSON 解析；禁止只拿手写 `out_time_ms=1234` 当毫秒去测（会和实现一起错）
- Git：不提交 `.venv`、巨大视频、密钥；提交按阶段，`feat(S3): ...`，不要 `update`；S10 必须验证 GitHub public 可打开

S1 信息表空值用 `—`；S3 起拿不到的字段用 `未知`。W32/W33 的 `{n}%` 相对源文件大小；体积几乎不变（变化 <1%）可写「体积基本不变」。

格式化：

- 大小：1024 进制，如 `12.3 MB`
- 时长：`00:01:23`
- 分辨率：`1920×1080`（乘号用 `×`）
- 帧率：整数写 `30 fps`，非整数最多 2 位
- 比特率：如 `2.1 Mbps`

### 11.2 command_runner

```python
@dataclass
class CommandResult:
    argv: list[str]
    returncode: int
    stdout: str
    stderr: str
    duration_ms: int

def run(argv: list[str], timeout: float = 30.0) -> CommandResult:
    ...
```

- `subprocess.run(argv, shell=False, capture_output=True, timeout=timeout, text=True, encoding="utf-8", errors="replace")`
- Windows：`creationflags=subprocess.CREATE_NO_WINDOW`，避免闪黑框
- 超时不要让整个应用崩溃，转成可展示错误

### 11.3 which_ffmpeg

```python
def find_ffmpeg() -> str | None: ...
def find_ffprobe() -> str | None: ...
```

顺序：`VFC_FFMPEG` / `VFC_FFPROBE`（文件确实存在）→ `shutil.which` → `C:\ffmpeg\bin\` → `C:\Program Files\ffmpeg\bin\`。返回绝对路径或 `None`。不要自动下载。

### 11.4 ffprobe_service

```python
def build_cmd(ffprobe: str, path: str) -> list[str]:
    return [ffprobe, "-v", "error", "-show_format", "-show_streams", "-of", "json", path]

def parse(stdout: str, path: str, size_bytes: int) -> MediaInfo: ...
```

**不要加 `--`。** ffmpeg 系工具不把 `--` 当选项终止符，会当成空名字未知选项而失败。`shell=False` + `list[str]` 已无注入风险，path 放最后即可。

缺字段 → `None`。视频流跳过 `attached_pic`。`avg_frame_rate` 为 `a/b` 时做除法，分母 0 则 `None`。

### 11.5 presets

```python
@dataclass(frozen=True)
class Preset:
    id: str
    name: str
    description: str
    suffix: str
    args: list[str]

def all_presets() -> list[Preset]: ...
def get_preset(preset_id: str) -> Preset: ...
```

`description` 写给人看，例如「微信和播放器一般都能打开」。`args` 必须是 list，不要一根字符串。  
`copy_mux.args` 必须含 `-map 0:v:0` `-map 0:a:0?` `-c` `copy` `-sn`。

若做可选硬件加速：另写 `hw_args_nvenc` 等完整 list，**禁止**在软件 `args` 上替换编码器名。

### 11.6 ffmpeg_service

```python
def build_thumbnail_cmd(ffmpeg: str, input_path: str, output_jpg: str, duration_sec: float | None) -> list[str]: ...

def build_convert_cmd(
    ffmpeg: str,
    input_path: str,
    output_path: str,
    preset: Preset,
    *,
    overwrite: bool = False,
    with_progress: bool = False,
) -> list[str]: ...

def parse_out_time_sec(line: str) -> float | None:
    """解析 -progress 的一行，返回已输出秒数。无匹配返回 None。"""

def percent_from_out_time_sec(out_time_sec: float, duration_sec: float) -> int:
    """0–99 整数。out_time 常略超 duration，禁止返回 100。duration<=0 不要除零。"""

def replace_output_suffix(path: str, suffix: str) -> str:
    """只替换后缀（suffix 含点，如 .mp3），保留目录和主干。"""

def is_same_media_path(path_a: str, path_b: str) -> bool:
    """Windows 上 abspath + normcase 后比较。用于开转前防毁源。"""

def format_argv_for_copy(argv: list[str]) -> str:
    """仅用于日志展示。Windows 用 subprocess.list2cmdline。禁止拿返回值去 shell=True 执行。"""

def humanize_ffmpeg_error(stderr: str) -> str:
    """1～2 句中文。无音轨 → W31；copy 失败 → W21。无音轨应在开转前就拦住，这里只是兜底。"""
```

`percent_from_out_time_sec`：**clamp 到 99**。`out_time` 常略超过 `duration`，收尾（moov、`+faststart` 重排）还要几秒。进度条到 100% 却没结束，用户会以为卡死。只有 `finished_ok` 时 UI 才把进度条和文案置为 100% /「转换完成」。

`parse_out_time_sec` 规则（顺序固定，禁止把 `out_time_ms` 当毫秒去除以 1000）：

1. **优先** `out_time=HH:MM:SS[.fraction]`（无歧义）
2. 否则 `out_time_us=` → 除以 `1_000_000`
3. 否则 `out_time_ms=` 作兜底：多数 ffmpeg 构建里这个字段实际是**微秒**。先按微秒换算（`/ 1_000_000`）；若结果已大于 `duration_sec` 的 2 倍，再按毫秒试（`/ 1000`）。单测必须带真实风格的 `out_time=00:00:12.345678` 行

抽帧（先 seek 再 decode；输出 **jpg**，`-q:v` 对 png 无效）：

```
[ffmpeg, "-ss", t, "-i", input, "-frames:v", "1", "-q:v", "3", "-y", output_jpg]
```

- 有时长：`t = str(max(duration_sec * 0.1, 0))`，普通小数
- 无时长：`t = "1"`
- 临时文件：`vfc_thumb_<pid>_<seq>.jpg`（**自增 seq**，禁止只用 pid：QPixmap 按路径缓存，换视频会显示上一张）
- 换视频或退出时删除旧文件

转换 S5（不要 `-y`，不要进度）：

```
[ffmpeg, "-hide_banner", "-i", input, *preset.args, output]
```

转换 S6+：在 `-hide_banner` 后插入 `-nostats`, `-progress`, `pipe:1`。  
用户确认覆盖后：在 `-i` **之前**插入 `-y`。

### 11.7 Worker 信号（名称固定）

**ProbeWorker(QThread)**  
`finished_ok = Signal(object)`  # MediaInfo  
`failed = Signal(str)`

**ThumbWorker(QThread)**  
`finished_ok = Signal(str)`  # jpg 路径  
`failed = Signal(str)`

**ConvertWorker**（必须 QProcess，禁止槽函数里 `subprocess.run` 转码）  
`started = Signal()`  
`log_line = Signal(str)`  
`progress = Signal(int)`  # S6 才发 0–99；100 只在 UI 收到 finished_ok 后设  
`finished_ok = Signal(str)`  
`failed = Signal(str)`  
方法：`start_convert(argv: list[str])`、`cancel()`

QProcess 硬规则：

- `setProgram(ffmpeg)` + `setArguments(其余)`，禁止拼成一根命令字符串
- **禁止** `setProcessChannelMode(MergedChannels)`：进度在 stdout，banner/错误在 stderr
- stdout 按块到达，必须保留**残行 buffer**，按 `\n` 切开再解析；最后一行常不完整
- 取消：`terminate()` → `waitForFinished(3000)` → 仍未结束再 `kill()` → 再 `waitForFinished`。**等进程结束后再删输出文件**；若 `PermissionError`，短等再删一次。ffmpeg 不 fork，不要「杀进程树」
- `closeEvent`：ProbeWorker / ThumbWorker / ConvertWorker 任一还在跑，必须先停再等结束，禁止直接销毁（否则 `QThread: Destroyed while thread is still running`）

## S6 转换过程体验

**目标**：进度、取消、覆盖确认、完成后打开文件夹、关闭窗口确认。  
**依赖**：S5 done。

### 必须修改

- `build_convert_cmd` 加入 `-nostats -progress pipe:1`
- `convert_worker.py` 解析进度
- 主窗口：覆盖对话框、打开文件夹、关闭事件
- `tests/test_progress_parse.py`

### 任务

- **S6-T1** 只从 **stdout** 解析进度。优先 `out_time=`，其次 `out_time_us`，`out_time_ms` 仅兜底且按第 11.6 节处理单位。`percent_from_out_time_sec` **clamp 到 0–99**，禁止转换中出现 100%。失败则 busy，不要卡在 0。残行 buffer 按 `\n` 切。**禁止 MergedChannels**。`finished_ok` 时 UI 再置 100%
- **S6-T2** 状态「正在转换… 37%」，有时长尽量估剩余时间。收尾阶段允许停在 99% 几秒，这是预期而不是卡死
- **S6-T3** 取消：terminate → wait → kill → wait；**再删**不完整输出；UI 可再次开始；状态「已取消」
- **S6-T4** 转换中再点开始：必须无效
- **S6-T5** 输出已存在：QMessageBox 问是否覆盖。否=不开始。是=命令加 `-y`
- **S6-T6** 完成后主按钮「打开所在文件夹」（`QDesktopServices` 或 `explorer /select,`）。再选新文件则回到「开始转换」
- **S6-T7** 转换中关窗：确认框 W19，确认则取消任务再退出。**无论是否在转换**，closeEvent 都要等 probe/thumb/convert 全部收尾
- **S6-T8** 单测 `parse_out_time_sec`：至少含 `out_time=00:00:12.345678`、`out_time_us=`、无关行返回 None。`percent_from_out_time_sec(duration+1, duration) == 99`，不得为 100。不要把 `out_time_ms=1234000` 断言成「1234 秒」
- **S6-T9** 用真实 ffmpeg 转 ≥2 秒视频：界面百分比必须出现明显非 0；完成前看不到假 100%。本阶段结束后写最短 README（选型一句 + 启动命令）并提醒推 GitHub

### 怎么验收

```powershell

```

- 进度会动（不是一直 0%；完成前不是假 100%）
- 取消后能立刻再转，且不完整文件已删除
- 覆盖行为与文案一致
- 选大文件后立刻关窗不崩
- S6 = done

建议提交：`feat(S6): 用 out_time 解析真实进度并在取消后释放文件再删除`
