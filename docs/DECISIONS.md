## 已锁定（项目开始前）

### D-01 界面选型：PySide6，明确否决网页 / Electron / tkinter
- 日期：2026-09-20
- 背景：需求写明「交付时优先看界面选型」；与「客户端」关联为 0 则不考虑。开发主力是 Python。选用 Qt。验收第一眼看的是 README 截图和窗口是不是桌面软件。
- 选项：
  - A **PySide6（Qt for Python）**
  - B tkinter / CustomTkinter：像课程作业，控件层次弱，和「Windows 客户端开发」关联弱
  - C Streamlit / Gradio / FastAPI+网页：浏览器页，会被当成 Demo 而不是客户端
  - D Electron / Tauri：能做桌面，但偏离 Python 主力，范围失控，3 天打不完
- 选择：A
- 原因：Qt 是成熟的桌面框架；能做出真正的 Windows 原生窗口；Python 可独立交付；许可证用 LGPL 的 PySide6，不用 GPLv3 的 PyQt6。对人的好处是打开就是「软件」而不是「网页作业」。
- 后果：不做网页 Demo；AI 若建议 tkinter/网页/Electron，直接拒绝。README 第一屏必须写「Windows 原生桌面客户端（PySide6/Qt）」并放主界面截图。

### D-02 进程模型：QProcess 异步调用 ffmpeg CLI
- 日期：2026-09-20
- 背景：需求允许命令行，不要求 ffmpeg API。产品不能转码时假死。
- 选项：A UI 线程 subprocess.run / B QProcess / C 线程里 subprocess + 信号
- 选择：B（C 作为备选）
- 原因：可读取进度、可取消、不冻窗口，符合「给人用」。
- 后果：禁止 `shell=True` 和同步阻塞调用。

### D-03 功能范围：按阶段交付，P2 全部砍
- 日期：2026-09-20
- 背景：目标是交付可用桌面客户端。开发按 `docs/阶段任务.md` 的 S0–S10 执行，不按日历切。
- 选项：大而全 / 主路径按阶段打磨
- 选择：主路径按阶段打磨
- 原因：后面阶段依赖前面验收；半成品功能比完整主路径更优先会交不出能用的东西。
- 后果：批量、剪辑、Agent/RAG、云转码明确不做；AI 禁止跳阶段。

### D-04 硬件加速降为可选；S7 必做「体积对比」
- 日期：2026-09-20
- 背景：硬件加速投入最大、收益最不明显——成功了用户只觉得快一点，失败了状态栏闪一句。更糟的是 NVENC/QSV 不认 x264 的 `-crf`，若只替换编码器名，命令必然失败，等于永远回退、白做。
- 选项：A 必做自动探测+回退 / B 砍掉换成完成后显示体积变化 / C 体积对比必做，硬件加速有时间再做且必须独立完整 args
- 选择：C
- 原因：`12.3 MB → 4.1 MB（压缩 67%）` 直接回答用户点「压缩体积」时的疑问，截图里立刻能看出来「在替人考虑」。
- 后果：禁止把 `libx264` 替换成 `h264_nvenc`；若做硬件加速，NVENC 用 `-cq`、QSV 用 `-global_quality`、AMF 用 qp，各写完整参数表。时间不够就砍 R20，不要砍主路径。
- 2026-09-21 补充：S7 执行时砍掉可选硬件加速（R20），只交付六项对人有用的 P1。

### D-05 打包策略：ffmpeg 外置，不打进 exe / 仓库
- 日期：2026-09-20
- 背景：完整 ffmpeg 体积大，许可证与更新都麻烦；产品需求命令行集成而不是发行版捆绑。
- 选项：A 把 ffmpeg.exe 打进包 / B 本机已安装 + 启动检测 / C 运行时自动下载
- 选择：B
- 原因：仓库干净；检测失败用人话引导（VFC_FFMPEG / PATH）；符合「第三方能力集成」考察。
- 后果：禁止提交 ffmpeg 二进制；禁止 S2 自动下载；README 必须写清安装方式。

### D-06 明确砍掉的 P2
- 日期：2026-09-20
- 背景：3 天内交的是可用客户端，不是平台。
- 选项：做一部分 P2 撑场面 / 全部砍掉并写进文档
- 选择：全部砍掉
- 原因：半成品按钮比没有更减分（规则：点了不能用视为质量事故）。
- 后果：不做批量队列、剪裁/旋转/字幕、自动更新、macOS/多语言、云转码/账号、内置模型/Agent/RAG、托盘常驻。

### D-07 ffprobe 命令不加 `--`
- 日期：2026-09-20
- 背景：规格曾写 `ffprobe ... -- <path>` 当选项终止符。
- 选项：A 保留 `--` 失败再记 D-07 去掉 / B 默认不加
- 选择：B
- 原因：ffmpeg 系解析器不支持 `--`，会当成空名字未知选项。`list[str]` + `shell=False` 已无注入问题。
- 后果：path 永远是最后一个参数；禁止再加 `--`。

### D-08 进度优先解析 `out_time=`，禁止把 `out_time_ms` 当毫秒
- 日期：2026-09-20
- 背景：许多 ffmpeg 版本里 `-progress` 的 `out_time_ms` 实际是微秒；按毫秒算百分比会变成真实值的 1/1000，界面永远 0%。手写 fixture 会和实现一起错。
- 选项：A 只用 out_time_ms/1000 / B 优先 `out_time=HH:MM:SS`，us 次之，ms 仅兜底并按微秒试算
- 选择：B
- 原因：`out_time=` 无单位歧义。S6 必须用真实视频核对进度会动。
- 后果：接口名为 `parse_out_time_sec`；单测必须包含真实风格的 `out_time=` 行。

### D-09 取消：等进程退出再删文件；关窗等所有 worker
- 日期：2026-09-20
- 背景：QProcess.kill() 后立刻 `os.remove` 会在 Windows 上 PermissionError。QThread 运行中销毁会崩。ffmpeg 不 fork。
- 选项：A 杀进程树再立刻删 / B terminate→wait→kill→wait→再删；closeEvent 等 probe/thumb/convert
- 选择：B
- 原因：T05 取消删文件、选大文件立刻关窗，这两条不处理就会挂。
- 后果：禁止 MergedChannels；stdout 残行 buffer；禁止 closeEvent 只处理「转换中」。

### D-10 最小可交付线与 GitHub 链接
- 日期：2026-09-20
- 背景：最终交付物是 GitHub 链接。S9/S10 若没有「推送并验证可访问」，仓库打不开则交付失败。十一个阶段若每个会话只推一个，节奏不慢，但随时可能被叫停。
- 选项：A 全部做完再推 / B S0–S6 可用后就有 public 仓库 + 最短 README + 截图，S10 无痕窗口复核
- 选择：B
- 原因：任何时候都有能发出去的链接；剩下往上加。
- 后果：S6 后写最短 README；S10-T7 无痕窗口打开仓库，确认 public、图片能显示、无 `.venv`/`dist`。exe 名用 ASCII：`VideoFormatConverter`。

### D-11 给人用的四条护栏：后缀、毁源、假 100%、先拦后转
- 日期：2026-09-20
- 背景：切预设不换后缀会写出扩展名错误的文件；输出写成源文件会不可逆毁掉视频；进度到 100% 后 faststart 还在写，用户以为卡死；无音轨提 MP3 若等失败再解释，不像给人用的软件。
- 选项：A 等 ffmpeg 报错再提示 / B 开转前校验 + 进度 clamp 99
- 选择：B
- 原因：产品必须「自己当用户走通、边界情况有处理」。毁源是数据损失，必须挡在点开始之前。
- 后果：切预设只换后缀；`is_same_media_path` 命中则 W34；百分比最高 99，`finished_ok` 才 100；无音轨选 MP3 立刻 W31 并禁用开始。S8 增加 T11–T13。

### D-12 S7 六项 P1：每项对人的好处
- 日期：2026-09-21
- 背景：产品需求优化必须对人有用，截图里能看出来；禁止为了「像专业」而加编码器开关。
- 选择与对人的好处（一句话）：
  - 记住设置：第二次打开不用重选目录和预设。
  - 输出文件名预览：改预设时立刻知道会写出 `.mp3` 还是 `.mp4`，避免扩展名错了才失败。
  - 打开文件：转完马上用系统播放器看画质，不必先翻文件夹。
  - 体积对比：点「压缩体积」后立刻知道有没有变小。
  - 详细日志：命令、退出码、关键 stderr 可复制，方便排查又不挡主路径。
  - 拖放打磨：多文件只取第一个视频、非视频用人话提示，不会 silently 吃错文件。
- 后果：不做 GPU 开关；硬件加速按 D-04 砍掉。
